# Fantasy Simulator

一款由大语言模型担任 GM 的单人奇幻文字冒险游戏。你创建角色，用自己的话决定行动，GM 根据完整的世界设定写出接下来的故事；角色状态、背包、任务、关系和声望由程序按规则结算并保存。

## 玩法介绍

### 想做什么就写什么

没有固定选项，也没有预设路线。在输入框里用自己的话写下角色要做的事，比如“去码头打听那艘失踪的货船”、“趁守卫换班溜进档案室”、“请她喝一杯，聊聊她的家乡”。GM 会根据世界设定、角色能力和当前局势写出结果：行得通的事会成功，力不能及的事会失败，选择会带来后果。

每一轮有三种推进方式：

- **自由行动**：以角色的身份行动或说话。
- **干涉命运**：跳出角色，描述你希望接下来发生什么，引导下一段剧情的走向。
- **重塑命运**：对最近一段结果不满意时，给出新的方向，让 GM 重写这一段。

在设置里可以调整剧情节奏（慢、快、动态）、剧情倾向（日常、平衡、战斗）、描写详细程度，以及 GM 如何称呼你的角色。

### 创建角色

角色创建分 13 步：从人类、羽族、海族、兽裔、精灵、龙族、矮人、魔族八个种族中选择，填写姓名、外貌、性格、身世，选择初始等阶、初始地区，并浏览大陆上的十二个势力。最后由模型根据你的设定生成角色候选，你可以要求修改，满意后再开始冒险。种族、地区与势力都配有设定图。

### 角色状态

- **短期资源**：生命（HP）、魔力（MP）、精神（SP）、精力（ST）。受伤、施法、精神冲击和长途跋涉都会消耗它们，休息和治疗可以恢复。生命归零即角色死亡，这是存档的结局，只能用“重塑命运”改写最后一段剧情。
- **长期属性**：体质、智力、魅力，取值 1 到 100，只会随着长期的锻炼、学习和重大经历缓慢变化。高智力帮你注意到线索，但不会替你做决定；高魅力让人更愿意听你说话，但不会让人无条件服从。
- **天赋与技能**：天赋是天生的特质，技能靠学习和训练获得。
- **经验与突破**：冒险积累经验，经验满后需要主动尝试突破才能升阶；越往高阶，突破越需要准备，高阶突破还要完成专门的突破任务。

### 战力

等阶是力量的根本，从 1 阶到 10 阶，基础战力从 100 增长到 100,000；10 阶是质的飞跃，通常只有另一位 10 阶强者才能正面抗衡。武器、防具和魔导器能提升战力，但普通装备的加成有上限，不能替代等阶；伤势、环境和特殊状态也会带来临时的增减。GM 不会无视明显的实力差距：面对强敌，正面硬拼往往会输，聪明的战术、撤退或交涉才是出路。

### 声望与羁绊

- **声望**：社会对你的评价，从 -100 到 100，分为公敌、恶名昭著、不受欢迎、中立、声名良好、受人敬重、威望卓著七档。分为整个大陆的综合声望和各势力的声望，只有公开或被人知道的行为才会影响声望。
- **羁绊**：重要人物对你个人的态度，同样从 -100 到 100，从死敌、仇恨、厌恶、普通，到友好、亲近、深厚羁绊。真诚的帮助、信守承诺会拉近关系，欺骗和背叛会让人疏远。深厚羁绊可以是友情、亲情、师徒或爱情，取决于你们真实的相处。高声望和高好感都不是控制手段，每个人仍会按自己的性格和立场行事。

### 任务与地区主线

旅途中会遇到各种委托和事件，由你决定接受、拖延还是拒绝。大陆上还有六条非强制的地区主线，只有在对应地点满足条件时才会出现，错过了也不影响冒险继续。

### 长期记忆与故事弧

故事越长，越需要 GM 记得过去发生过什么：

- **故事弧**：较早的剧情每积累 25 段，就会自动整理成一个故事弧，用一段梗概记下这段旅程，并单独列出仍未解决的事项。故事弧多了以后会继续合并。完整的原始剧情始终保存在“纪事”里，随时可以回看。
- **长期记忆**：关键线索、承诺、人物关系的变化等会被记成长期记忆。每一轮，程序会挑出和当前地点、人物、话题最相关的记忆交给 GM。配置了可选的嵌入模型后，换一种说法提到旧事也能被想起。
- 在“记忆管理”里可以逐条删除不需要的记忆，也可以让 GM 回顾全部记忆，清理已经解决、过期或不重要的内容。

### 场景图片

配置生图模型后，可以为当前剧情生成一张插图：GM 先根据剧情整理画面描述，你可以修改描述，选择横图、方图或竖图和画质，再生成图片。图片生成由 OpenAI 收费。

### 存档

可以同时保留多个存档，每个存档独立保存角色、剧情和所有记录。存档可以导出为 JSON 文件，在另一台电脑上导入继续游玩；导出的文件不包含任何 API 密钥。

## 启动

普通玩家可以直接到 [Releases](https://github.com/AeolionGKQ/Fantasy-World-Simulator/releases) 下载 Windows 整合包，解压后即可运行，不需要安装 Python 或 Node.js。

需要 Windows（已在 Windows 11 上测试）。双击根目录的 `启动游戏.bat`，脚本会用项目自带的 Python 运行时启动服务，等待服务就绪后打开 `http://127.0.0.1:8000`。

仓库已包含构建好的前端，日常启动不需要安装 Node.js。只有 `apps/web/dist` 不存在时，脚本才会调用本机的 Node.js/npm 安装依赖并构建。

关闭名为 `Fantasy Simulator Server` 的终端窗口即可停止服务。

## 连接模型

首次进入后打开“设置”：

- **剧情模型**：支持 OpenAI 兼容和 Anthropic 兼容两种接口，填写服务地址、模型名和密钥即可。建议选择能读取较长上下文的模型，每轮生成都会附带完整的世界设定。
- **生图模型**：可选，目前只支持 OpenAI 官方服务。
- **嵌入模型**：可选，支持 OpenAI 兼容的嵌入接口，需填写包含 `/v1/embeddings` 的完整网址。测试通过并打开“使用向量召回”后，长期记忆按意思相近程度召回；未配置、关闭或暂时连不上时自动改用关键词召回，剧情不受影响。开启后，长期记忆内容和每轮的行动描述会发送给该服务。

“测试连接”会发送很小的请求检查连通性和思考开关是否可控，可能产生少量费用；测试结果和失败原因显示在测试按钮旁。侧栏底部显示各模型的连接状态，只读取最近一次测试或生成的结果，不会另外请求模型服务。

## 数据与密钥

- 游戏数据保存在 `apps/api/.data`，不会提交到仓库。
- API Key 在 Windows 上用当前用户的 DPAPI 加密后保存；加密不可用时只保存在内存中，重启后需要重新填写。
- 导出的存档不包含任何密钥。

## 世界设定

`canon/` 文件夹存放游戏读取的全部规则与世界正典：GM 行为规则、属性/经验/战力/声望规则、世界基础、地理、种族、势力、人物、奇观、货币、地区主线以及 GM 写作规范。服务启动时读取这些文档，GM 每轮生成时都会看到它们的完整内容。

修改这些文档后重启服务即可生效，但只影响之后新建的存档：每个存档在创建时会冻结当时的设定，之后一直沿用。角色创建界面上的种族、地区、势力介绍另存在 `apps/api/catalog.py` 中，需要单独修改。

## 项目结构

```text
启动游戏.bat        Windows 启动器
canon/              规则与世界正典文档
apps/api/           后端：只依赖 Python 标准库
apps/web/           前端：React + Vite，dist/ 为构建产物
runtime/python/     随项目分发的 Python 运行时
```

## 开发与测试

在项目根目录执行：

```powershell
cd apps/web
npm install
npm run dev      # 开发服务器，/api 转发到 127.0.0.1:8000
npm run test
npm run build    # 修改前端后需要重新构建，游戏服务使用 dist/
cd ../..

.\runtime\python\python.exe apps\api\server.py                        # 单独启动后端
.\runtime\python\python.exe -m unittest discover -s apps\api\tests    # 后端测试
```
