# 前端视觉与动效改进计划

## 1. 目标与边界

让界面在保持现有“明亮的冒险绘本”方向（见 `DESIGN.md`）的前提下，层次更清楚、阅读更舒适，并为页面切换、页签切换、步骤切换、弹窗和反馈加入连贯的过渡，消除“直接刷新”的生硬感。

边界：

- 不改变品牌方向：保留浅蓝纸面、暖白卡片、深蓝描边、向日葵黄点缀和偏移阴影这一手绘质感，只收敛它的使用范围。
- 不新增依赖做动画：动效只用 CSS、View Transitions API 和 Web Animations API，不引入 framer-motion / GSAP。
- 不新增断点：仍然只有 1024px 一档，移动端规则继续写在各文件末尾的 `@media (max-width: 1023px)` 块中。
- 后端只做两处已确认的增量修改：存档列表增加最近一段剧情的标题与地点（D-05），新增剧情 AI / 图片 AI 连接状态（D-06）。其余接口不变。
- 所有动效遵守 `prefers-reduced-motion: reduce`；不支持 View Transitions 的浏览器直接切换，不报错。
- 本轮只给出计划，不修改代码。实现时按第 9 节的阶段推进，每完成一项在本文勾选。

编号约定：`B` 为缺陷，`V` 为视觉问题，`M` 为动效，`D` 为决定（已全部确认，见第 6 节），`F` 为由决定引出的新功能。

## 2. 审查方式与原始结果

- 运行了 taste-skill 的 `lint.mjs`（源码扫描）和 `inspect.mjs`（真实浏览器在 1440 / 768 / 390px 下测量与截图）。
- 用无头 Chrome 截取了：首页、游戏页全部 8 个页签、角色创建（第 1 步、第 5 步）、设置页、新建存档弹窗、404，桌面 1440×900 与手机 390×844 各一套。

工具结果摘要：

| 工具 | 结果 | 处理意见 |
| --- | --- | --- |
| lint | 86 FAIL / 55 WARN：阴影 30、细分隔线 52、1px 描边框 53、渐变 1、等宽字体 2、“emoji” 1、`100vh` 2 | 该技能面向营销落地页，阴影与描边是本项目刻意的绘本质感，**不按其规则整体删除**，只在 V-01 中收敛范围。等宽字体用于问题编号（trace id），属于代码性质文本，保留。“emoji” 是步骤导航的 `✓`，保留。渐变是骨架屏闪光，保留。`100vh` 见 B-06。 |

## 3. 已发现的缺陷（B）

| 编号 | 问题 | 位置 | 修复方案 |
| --- | --- | --- | --- |
| B-01 | `index.html` 声明 `<meta name="color-scheme" content="dark">` 与 `theme-color #101719`，而应用是浅色主题。CSS 加载前画布按深色绘制，刷新时可能先闪一下深色；浏览器 UI 颜色也不一致。 | `apps/web/index.html:6-7` | 改为 `color-scheme: light`，`theme-color` 改为 `--bg` 的值 `#edf4ff`；在 `<html>` 上加内联 `style="background:#edf4ff"` 防止首帧闪烁。 |

| B-03 | 弹窗打开后焦点落在右上角关闭按钮上，并显示粗焦点框；输入框上的 `autoFocus` 失效。原因：React 在挂载时执行 `autoFocus`，随后 `Modal` 的 `useEffect` 调用 `showModal()`，浏览器把焦点移到对话框内第一个可聚焦元素（关闭按钮）。 | `components/Modal.tsx:11-16`；`NewSaveModal.tsx:33`、`RenameSaveModal.tsx:26`、`DeleteSaveModal.tsx:25` | `showModal()` 之后主动聚焦 `dialog.querySelector("[data-autofocus]")`，没有则聚焦第一个输入框；各弹窗把 `autoFocus` 换成 `data-autofocus`。 |
| B-04 | 角色创建切换步骤时页面跳动：步骤内的输入框带 `autoFocus`，新步骤挂载时浏览器把页面滚到输入框（第 5 步截图中整页被滚走）。 | `AgeStep.tsx:18`、`GenderStep.tsx:16`、`PresetTextStep.tsx:34`、`TextStep.tsx:15-16` | 改为挂载后 `focus({ preventScroll: true })`（可做成 `useAutoFocus` 小钩子），并由 M-05 统一处理步骤切换后的滚动位置。 |
| B-05 | 移动端侧栏关闭时，`transform: translateX(-101%)` 不足以把 `12px 0 32px` 的阴影移出屏幕，所有手机截图左缘都有一道灰色渐变。 | `styles/layout/shell.css` 移动端块中的 `.sidebar` | 关闭状态不带阴影，只在 `.sidebar.open` 上加阴影；或把位移改为 `translateX(calc(-100% - 48px))`。 |
| B-06 | `min-height: 100vh` 在手机上会随地址栏伸缩跳动。 | `styles/layout/shell.css:4`、`:218`、`:306` | 改为 `100dvh`（`body` 已在用 `100dvh`），包括 `#main-content` 的 `calc(100vh - …)`。 |
| B-07 | 加载完成后正文没有任何入场：游戏页的加载态与正文最外层都是 `<div className="page game-page">`，React 复用同一元素，`page-in` 动画不会重播，正文是“冒”出来的。角色创建、设置页同理。 | `features/game/GameWorkspace.tsx:19-21`、`:61`；`CharacterWizard.tsx:26-27` | 见 M-02。 |
| B-08 | `page-in` 只有 4px 位移、没有透明度变化，200ms，几乎感觉不到，又会和 View Transition 叠加。 | `styles/layout/page.css:7`、`styles/base.css` 的 `@keyframes page-in` | 由 M-01 / M-02 取代后删除。 |
| B-09 | 减弱动效规则只匹配 `*`、`::before`、`::after`，加入 View Transition 后 `::view-transition-*` 伪元素不受控制。 | `styles/base.css` 末尾 | 见 M-19。 |

## 4. 视觉问题与修改方案（V）

### V-01 “处处强调”导致层次扁平

现状：首页标题区、最近档案列表、剧情阅读列、建议行动列、步骤卡片、设置分区、弹窗都使用 2px 深色描边 + 偏移阴影；卡片内部又套描边卡片（角色页的状态条、长期属性卡，建议行动里的选项卡，设置中的每个控件组）。一屏同时有 3–6 个“同等重要”的表面，视线没有落点。

方案：定义四级表面，写入 `tokens.css` 与 `DESIGN.md`：

| 级别 | 用途 | 样式 |
| --- | --- | --- |
| L0 页面 | 页面背景 | `--bg`，无边框 |
| L1 主表面 | 每个页面区域最多一个：剧情阅读列、当前步骤卡片、当前页签面板、设置分区、弹窗 | 2px `--outline` 描边 + 5px 偏移阴影（保留现有绘本质感） |
| L2 内部分组 | 状态条、属性卡、选项卡、记录列表项 | 不加描边，只用一级色阶（新令牌 `--surface-sunken`）区分 |
| L3 可交互项 | 选项按钮、芯片 | 默认 1px `--line`；悬停/选中才加深描边或填色 |

具体调整：

- [x] 首页 `.home-heading` 不再是卡片，改为普通页面标题（与 V-07 一起做）。
- [x] 剧情页：阅读列保持 L1；建议行动列从整块向日葵黄底改为 L1 白底，向日葵黄只留给标题前的小标记（见 V-05）；内部选项卡降到 L3。
- [x] 角色页签：状态条与长期属性卡降为 L2。
- [x] 设置页：分区保持 L1，分区内不再出现第二层描边。

### V-02 字号失控，中文小字过小

现状：样式中约有 40 种不同的字号（`.7rem`、`.72rem`、`.74rem`、`.75rem`、`.78rem`、`.8rem`、`.82rem`、`.84rem`…），辅助信息大量使用 11–12px，中文在 12px 以下很难辨认（如存档列表元信息、剧情元信息行、状态条说明、页签文字 12.8px）。

方案：新增字号令牌，所有 `font-size` 只引用令牌：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--text-xs` | 13px | 元信息、计数、问题编号（中文最小字号） |
| `--text-sm` | 14px | 辅助说明、表单提示、页签 |
| `--text-base` | 16px | 界面正文 |
| `--text-read` | 18px | 剧情正文、世界资料正文 |
| `--text-lg` | 22px | 区块标题 h2 |
| `--text-xl` | 28px | 页面标题 h1 |
| `--text-display` | `clamp(32px, 2.8vw, 44px)` | 角色名、剧情章节标题、首页标题 |

- [x] `tokens.css` 新增上述令牌。
- [x] 逐文件替换硬编码字号（约 130 处），桌面密度令牌 `--game-tab-font-size` 并入 `--text-sm`。
- [x] 侧栏标题“存档”去掉大写字母间距样式（`letter-spacing: .08em; text-transform: uppercase` 对中文无意义）。

### V-03 标题与正文对比偏弱

现状：页面主标题 28px，正文 16px，比例不到 2；游戏页角色名与普通页面标题同级。

方案：

- [x] 游戏页头部角色名使用 `--text-display`，时间与地点行升到 `--text-base`。
- [x] 首页标题“冒险档案”使用 `--text-display`。
- [x] 其余页面 h1 保持 `--text-xl`。

### V-04 剧情阅读排版

现状：剧情正文是黑体 16px、行高 2.05、每行最多 45em（约 45 个汉字），行距过松、行过长，长时间阅读缺少“书页感”。

方案：

- [x] 正文改为 `--text-read`（18px），行高 1.85，段距 1em，每行最多 36em（约 36 个汉字）。
- [x] 剧情章节标题与正文改用宋体（D-01 已确认：打包到本地），界面其他部分继续用黑体。
  - 安装 `@fontsource/noto-serif-sc`（锁定版本，写入 `package-lock.json`），只引入 400 与 700 两个字重的 CSS；字体按 Unicode 范围分片，浏览器只下载页面实际用到的分片，全部随 `dist` 本地提供，不访问网络。
  - 新增令牌 `--font-reading: "Noto Serif SC", "Source Han Serif SC", "Songti SC", serif;`，只用于剧情阅读列、章节标题和世界资料阅读列。
  - 字体加载使用 `font-display: swap`；首屏只用黑体的页面不会触发宋体下载。
  - 在 `THIRD_PARTY_NOTICES.md` 补充 Noto Serif SC 的 SIL Open Font License 1.1 声明。
  - 构建后记录 `dist` 体积变化，写入本文第 10 节的验收记录。
- [x] 元信息行（时间 · 地点 · 第 N 段）升到 `--text-xs` 并使用 `--muted`。
- [x] 世界资料阅读列同步采用同一套阅读排版。

### V-05 配色不一致

现状：

- 约 40 处颜色硬编码，未走令牌，例如角色状态条的暖米色 `#f7f4ec` / `#ddd7c9`（`projections.css:112-113`、`:170-171`）与整体蓝色体系不协调；各种偏移阴影色 `#cfb35a`、`#c9ad56`、`#b49b4e`、`#243777` 等。
- 向日葵黄同时用于品牌标、当前页签、当前步骤、工具栏“新建存档”、整块建议行动面板，失去“当前位置”的含义。
- “新建存档”在工具栏是黄色按钮，在首页是靛蓝主按钮，同一操作两种主色。
- “游戏档案”小标签使用成功绿色（`.ready-mark`），把状态色用作装饰。

方案：

- [x] 新增令牌：`--surface-sunken`、`--sunflower-strong`、`--sunflower-shadow`、`--primary-shadow`、`--shadow-overlay`，把硬编码颜色全部换成令牌；验收时 `features/`、`components/`、`layout/` 下不再出现十六进制颜色。
- [x] 状态条改用 `--surface-sunken`。
- [x] 向日葵黄只保留两个角色：品牌标记、当前位置（当前页签、当前步骤）。建议行动面板、工具栏按钮不再用黄色。
- [x] 工具栏“新建存档”改为与“导入存档”同级的图标文字按钮；首页保留靛蓝主按钮作为每屏唯一主操作。
- [x] 删除游戏页头部的“游戏档案”小标签（时间地点行已经说明上下文）。

### V-06 圆角不统一

现状：约 12 种圆角（3、7、10、11、12、13、14、16、18、20、22px、50%）。

方案：

- [x] 新增 `--radius-sm 8px`（芯片、小按钮）、`--radius-md 12px`（按钮、输入框）、`--radius-lg 16px`（L2 分组、设定图）、`--radius-xl 22px`（L1 主表面、弹窗）、`--radius-full 999px`（圆点、徽章），全部替换。

## 5. 动效方案（M）

### 5.1 动效令牌

在 `tokens.css` 中新增，所有动效只用这些值：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--dur-press` | 100ms | 按下 |
| `--dur-state` | 180ms | 悬停、选中、颜色变化 |
| `--dur-exit` | 140ms | 元素离场 |
| `--dur-enter` | 240ms | 元素入场、页面切换 |
| `--dur-move` | 320ms | 指示块滑动、共享元素形变 |
| `--ease-out` | `cubic-bezier(0.25, 1, 0.5, 1)`（现有 `--ease`） | 入场、状态变化 |
| `--ease-in` | `cubic-bezier(0.5, 0, 0.75, 0)` | 离场 |
| `--ease-move` | `cubic-bezier(0.65, 0, 0.35, 1)` | 指示块滑动 |
| `--rise` | 8px | 入场上移距离 |
| `--slide` | 24px | 方向性滑动距离 |
| `--stagger` | 50ms | 依次出现的间隔 |

原则：只动 `transform` 和 `opacity`；离场比入场快；一次交互最多一个“主运动”；动画期间不阻塞输入超过 320ms。

### 5.2 实现架构

1. **路由改为 data router。** React Router 7 的 `viewTransition` 与 `navigate(to, { flushSync })` 只在 data / framework 模式下可用，当前 `main.tsx` 使用的 `<BrowserRouter>` 是声明式模式。改为：

   ```tsx
   const router = createBrowserRouter([{ path: "*", element: <App /> }]);
   createRoot(root).render(<StrictMode><RouterProvider router={router} /></StrictMode>);
   ```

   `App` 内部的 `<Routes>` 保持不变，改动只在 `main.tsx`。

2. **一个统一的过渡辅助函数** `src/app/viewTransition.ts`：

   ```ts
   runViewTransition(kind: "route" | "tab" | "step" | "turn", update: () => void, direction?: "forward" | "back")
   ```

   - 不支持 `document.startViewTransition` 或用户开启减弱动效时，直接执行 `update`。
   - 执行前在 `<html>` 上设置 `data-vt="<kind>"` 和 `data-vt-dir="<direction>"`，`transition.finished` 后清除。CSS 根据这两个属性决定哪些元素获得 `view-transition-name`、往哪个方向滑，避免不同场景的命名元素互相干扰。
   - 根元素设为 `view-transition-name: none`，侧栏与工具栏在切换中保持静止，只有指定区域运动。

3. **`useAppNavigate()` 钩子**：包装 `useNavigate`，内部调用 `runViewTransition("route", () => navigate(to, { flushSync: true }))`。所有 `navigate(...)`（约 15 处）和 `<Link>`（约 9 处，改为点击时调用该钩子或使用 `viewTransition` 属性）统一走它。

4. **新样式文件** `styles/components/motion.css`（放入 `components` 层）：集中定义 `::view-transition-*` 规则和通用入场类；关键帧继续放在 `base.css`。

### F-02 侧栏底部的模型服务状态（D-06）

目的：侧栏不再放设置入口后，用底部状态让玩家一眼看出剧情 AI（以及可选的图片 AI）是否已配置、是否连得上。

状态定义（剧情 AI 与图片 AI 各自独立计算）：

| 状态 | 条件 | 侧栏显示 | 标记 |
| --- | --- | --- | --- |
| `not_configured` | 服务地址或模型为空，或没有可用的 API Key（包括密钥只保存在内存、重启后丢失的情况） | “剧情 AI 未配置” | 空心灰点 |
| `unverified` | 配置完整，但当前配置还没有任何一次成功或失败的检查记录 | “剧情 AI 已配置，未测试” | 空心黄点 |
| `connected` | 当前配置最近一次检查成功（连接测试通过，或一次真实生成成功） | “剧情 AI 已连接 · 模型名” | 实心绿点 |
| `failed` | 当前配置最近一次检查因连接类问题失败 | “剧情 AI 连接失败” | 实心红点 + “!” |

- 状态用文字、符号和颜色共同表达，颜色不是唯一编码。
- “当前配置”以配置指纹判断：`sha256(协议 | 服务地址 | 模型 | sha256(API Key))`。修改地址、模型或密钥后，旧记录自动失效，状态回到 `unverified`。指纹中只含密钥的哈希，不保存密钥本身。
- 计为连接失败的错误码：`MODEL_AUTH_FAILED`、`MODEL_NETWORK_ERROR`、`MODEL_TIMEOUT`、`MODEL_NOT_FOUND`、`MODEL_SERVICE_ERROR`。不改变状态的错误码：`MODEL_RATE_LIMITED`、`MODEL_OUTPUT_FORMAT`、`MODEL_CONTEXT_LENGTH_EXCEEDED`、`MODEL_OUTPUT_TOO_LARGE`、`MODEL_REQUEST_REJECTED`（这些说明服务可达，问题在请求或输出）。
- 状态查询**从不调用模型服务**，不产生费用；只读取已记录的结果。

## 11. 实现记录

记录实现过程中与上文计划不同的地方及原因。

### 阶段一

- B-03：四个存档弹窗的输入框（含导入弹窗的文件选择框）统一使用 `data-autofocus`，由 `Modal` 在 `showModal()` 之后聚焦。导入弹窗的文件框是透明覆盖层，因此给可见的选择区域补了 `:focus-within` 与键盘焦点框。
- B-04：`useAutoFocus` 是回调 ref（元素挂载时聚焦），这样“性别 → 其他描述”这类稍后才出现的输入框也能获得焦点。
- B-02：新增只改透明度的 `soft-pulse` 关键帧，而不是复用会缩放的 `status-pulse`（44px 方块缩放会显得跳动）。

### 阶段二

- `useAppNavigate` 放在 `app/viewTransition.ts` 中，没有单独建文件。普通路由切换使用 React Router 自带的 `viewTransition`（`<Link viewTransition>` 与 `navigate(to, { viewTransition: true })`）；只有需要方向的步骤切换才走 `runViewTransition`。
- 额外加入 `<ScrollRestoration />`（data router 才能使用）：新页面从顶部开始，浏览器前进后退恢复原滚动位置。之前切换页面会保留上一页的滚动位置。
- 加载中的页面（`.page-loading`）不参与路由过渡命名。实测发现：被捕获的页面元素在过渡中途被替换（加载态 → 内容）会让过渡提前结束（约 50ms）。改为不捕获加载态后，旧页面完整淡出（约 315ms），内容加载完成后由 `.page-enter` 入场。
- M-15 以及后续 M-03、M-04、M-05 的“滑动高亮块”不用 View Transition 命名，改用 `useSlidingIndicator`：测量当前项的位置，由 CSS transform 过渡移动。原因是被命名的高亮块在过渡期间会作为快照画在最上层，盖住文字。
- 工具栏标题过渡改为按原始宽度交叉淡化；默认的尺寸形变会把两段不同长度的文字横向拉伸。

### 阶段三

- **修复了一个导致“每一步都重新加载”的既有问题**：应用内嵌的 `<Routes>` 中，React Router 的 `useNavigate()` 每次地址变化都会返回新函数；角色创建的草稿加载依赖它，于是每切换一步都会重新请求存档、草稿和世界资料，并闪一下加载骨架。`useAppNavigate` 现在返回稳定的函数，步骤切换不再重新加载，过渡可以完整播放（约 297ms）。审阅页的加载同样受益。
- M-05 切换步骤后由 `<ScrollRestoration />` 回到页面顶部（标题、步骤导航与卡片顶部都在视口内），没有单独计算“卡片顶部”的滚动位置。
- 步骤卡片中 `.step-body`（标题、说明、校验提示、步骤内容）参与滑动，底部“上一步 / 保存并下一步”按钮保持不动。
- M-04 剧情输入模式按钮补充了 `aria-pressed`。
- M-16 种族、地点、势力条目切换时，整块资料（设定图与正文）交叉淡化；单选芯片与分段按钮补充了底色、边框过渡。
- V-09 已随 M-03 一并完成：选中块由滑动元素承担，页签下方改为 1px 线，手机端加入滚动吸附与两端渐隐。

### 阶段四

- M-06 弹窗用 CSS 关键帧动画（`dialog[open]` 入场、`.closing` 离场），没有使用 `@starting-style`：效果相同，兼容性更好。关闭路径（×、Esc、带 `data-modal-close` 的取消按钮）都先播放离场，再以原生 `dialog.close()` 关闭，浏览器因此会把焦点还给打开弹窗的按钮（之前直接卸载，焦点会丢到页面上）。提交成功后由父组件直接卸载，不播放离场（随后通常就是路由过渡）。
- 浏览器规定：没有用户操作激活时，Esc 的取消不能被拦截。真实点击打开的弹窗按 Esc 会播放离场；脚本打开的弹窗按 Esc 会直接关闭，功能不受影响。
