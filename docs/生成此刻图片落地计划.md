# “生成此刻图片”功能落地计划

## 1. 目标与边界

在游戏剧情区顶部右侧增加“生成此刻图片”入口。功能以当前正在查看且仍为最新的剧情节点为画面来源，先由现有剧情模型基于完整规则、世界设定、角色状态、剧情历史、长期记忆和故事弧生成一段可编辑的文生图提示词，再由用户确认后调用 OpenAI `gpt-image-2.5-sunburst` 生成图片。

首版边界：

- 仅支持 OpenAI Images API 与固定模型 `gpt-image-2.5-sunburst`。
- 只做文生图，不做垫图、局部编辑、蒙版或多图批量生成。
- 每个存档同时最多存在一个未复位的图片会话。
- 图片会话不改变游戏权威状态，不创建剧情节点，不进入纪事、长期记忆或故事弧。
- 应用侧图片、提示词草稿和任务状态仅保存在本机，不进入存档导出；提示词生成会把完整故事上下文发送给已配置剧情模型服务，确认后的提示词会发送给 OpenAI，服务商侧处理和保留遵循对应账户的数据控制策略。
- 本轮只提供方案，不修改业务代码。

## 2. API 可行性结论

官方模型页确认 `gpt-image-2.5-sunburst` 支持文本和图片输入、图片输出，并支持 Image generation endpoint。首版采用最直接的 Images API：

```http
POST {base_url}/images/generations
Authorization: Bearer {image_api_key}
Content-Type: application/json

{
  "model": "gpt-image-2.5-sunburst",
  "prompt": "用户确认后的提示词",
  "size": "1536x1024",
  "quality": "high",
  "output_format": "png",
  "n": 1,
  "moderation": "auto"
}
```

预期响应从 `data[].b64_json` 读取，严格 Base64 解码后保存为本地图片。实现时以官方 Images API 最新字段为准补一次真实连接测试；不要依赖模型的结构化输出或函数调用能力。

图片生成界面允许用户在每次请求前选择质量、分辨率和方向，服务端把选择映射到 Images API 的 `quality` 与 `size` 字段；`output_format=png` 和 `n=1` 继续固定。默认使用横图 `1536x1024`、`quality=high`。

### 2.1 可配置图片参数

官方 Image generation 指南确认 `gpt-image-2.5-sunburst` 支持以下字段：

- `quality`：`low`、`medium`、`high`、`xhigh`、`max`、`auto`。质量越高通常耗时和费用越高；界面提供“低 / 中 / 高 / 超高 / 最高 / 自动”，默认“高”。
- `size`：标准尺寸 `1024x1024`、`1536x1024`、`1024x1536`，也支持 `auto`。首版只开放三个明确尺寸，不开放任意自定义宽高，便于校验、预览和成本说明。
- Images API 没有独立的 `orientation` 字段。横/竖图是 UI 语义，后端映射为 `size`：横图=`1536x1024`，竖图=`1024x1536`，方图=`1024x1024`。

为了让“方向”和“分辨率”都可配置且不会互相矛盾，界面采用一个组合式“画幅”选择，而不是两个独立但可能冲突的控件：

```text
画幅
  横图  1536 × 1024
  方图  1024 × 1024
  竖图  1024 × 1536

图片质量
  低 / 中 / 高 / 超高 / 最高 / 自动
```

用户看到的“分辨率”和“方向”均由画幅选项明确表达。若以后官方开放更多稳定尺寸，再扩展允许列表，不接受客户端直接传任意 `size`。

## 3. 用户流程

```text
未配置生图模型
  → 按钮呈不可用样式但仍可点击
  → 弹出明确提示并提供“前往设置”

已配置
  → 点击“生成此刻图片”
  → 创建绑定当前节点的图片会话
  → 剧情模型生成提示词
  → 用户审阅、修改提示词
  → 点击“生成图片”
  → Sunburst 后台生成
  → 页面显示进度
  → 成功后显示图片，可放大、保存、修改提示词后再次生成
  → 点击“完成”清理会话并回到剧情页
```

“复位”定义为用户显式点击“完成”。离开页面、切换页签、切换存档、刷新浏览器或重启本地服务都不能自动复位。再次点击入口时，恢复该存档当前未完成会话及进度。

若会话绑定节点已不再是最新节点，仍允许查看、保存和完成已有图片，但禁止以该旧会话直接改绑新节点。用户必须先完成旧会话，再为新节点创建会话。

## 4. 后端设计

### 4.1 独立生图设置

在全局设置中增加 `image_model`，不要复用剧情模型配置：

```json
{
  "base_url": "https://api.openai.com/v1",
  "model": "gpt-image-2.5-sunburst",
  "timeout_seconds": 300,
  "configured": true
}
```

约束：

- `model` 只允许 `gpt-image-2.5-sunburst`。
- 首版只允许 HTTPS `api.openai.com`，禁止自定义主机、跨主机重定向和内网地址；允许输入 OpenAI 根地址并规范化 `/v1`。
- 生图 API Key 独立使用 DPAPI 保存，读取设置时只返回配置状态和掩码。
- 不复用文本模型的并发上限；生图固定并发 1，避免高成本重复请求。

新增接口：

- `PUT /api/settings/image-model`
- `POST /api/settings/image-model/test`
- `GET /api/settings` 增加脱敏的 `image_model` 区域

“测试连接”默认只通过 `GET /v1/models/{model}` 检查鉴权和模型可见性，不生成图片；另设“执行真实生图测试”，明确说明会产生费用后才发送最低质量图片请求。模型可见不等于账户一定具备生成权限，正式请求错误仍需原样反馈。

### 4.2 密钥存储

扩展 `SecretStore` 为命名密钥容器，至少包含：

- `narrative_api_key`
- `image_api_key`

迁移时把现有单密钥映射到 `narrative_api_key`。DPAPI、内存回退、原子写入、密钥不进入日志/导出等现有安全边界保持不变。

### 4.3 图片会话与任务表

新增迁移与独立表，建议拆为会话和生成尝试：

```text
image_sessions
  id, save_id, source_turn_id, source_turn_version_id
  source_state_version, status
  prompt_draft, prompt_revision
  selected_size, selected_quality, settings_revision
  frozen_context_json, context_manifest_json
  created_at, updated_at, completed_at

image_prompt_attempts
  id, session_id, request_id, request_fingerprint
  status, provider_protocol, provider_endpoint, provider_model
  error_code, error_message, retryable
  created_at, updated_at

image_attempts
  id, session_id, request_id, prompt_revision
  status, provider_model, requested_size, requested_quality
  image_relative_path, mime_type, byte_count, sha256
  error_code, error_message, retryable
  created_at, updated_at
```

数据库约束：

- 每个 `save_id` 只能有一个 `completed_at IS NULL` 的会话。
- 每个会话只能有一个 queued/running 图片尝试。
- 提示词任务和图片任务各自只能有一个 queued/running 尝试，并分别保留尝试历史。
- `request_id` 幂等，提示词版本参与请求指纹。
- `size` 与 `quality` 也参与请求指纹；每次 attempt 保存实际请求参数，旧图片始终能还原其生成设置。
- 会话必须绑定存在的当前 turn/version；创建时记录源状态版本。
- 创建会话时在同一短事务内冻结 state、目标 turn/version、所选历史、记忆、故事弧、地点、内容版本及叙事设置；manifest 记录该冻结载荷的哈希，worker 不再读取后续变化的实时状态。

状态机：

```text
session: active → completing → completed
prompt attempt: queued → running → succeeded | failed | interrupted | cancel_requested → cancelled
image attempt: queued → running → succeeded | failed | outcome_unknown | interrupted | cancel_requested → cancelled
failed/interrupted/cancelled → 新建一次 queued attempt
```

提示词生成和图片生成作为同一会话的两类独立后台尝试，便于重启恢复和错误重试。服务启动时把中断的运行态改为 `interrupted`，由用户显式重试，避免隐藏费用。会话展示状态由两类尝试和当前草稿确定，不与单个 attempt 状态混用。关键状态、外键和部分唯一性均建立数据库约束。

### 4.4 提示词生成

新增 `image-prompt/1` 契约，模型只返回：

```json
{
  "prompt": "完整可直接用于文生图的提示词"
}
```

提示词必须使用简体中文，便于玩家直接理解和修改；专有名词优先沿用设定中的中文名称。契约约束：非空、最大约 8000 字符、不含 Markdown 围栏、不输出 URL、文件路径或 API 参数。

新增 `ContentRegistry.build_image_prompt_messages()`，复用现有上下文装配的全部来源：

- 六份规则原文与八份世界正典原文
- 当前角色与权威状态
- 当前节点完整正文及当前版本
- 早期摘要、近期完整节点
- 长期记忆与故事弧
- 正典 NPC 与地点目录

补充专用视觉指令：只描绘当前节点已经发生或明确可见的内容；不得推进剧情、创造新事件或替玩家行动；保持人物种族、外貌、服饰、装备、地点、时间、天气和情绪一致；根据用户所选横图、方图或竖图生成对应构图描述；避免界面文字、水印和不可验证细节。

提示词生成继续使用已配置的剧情模型协议、思考设置、超时和共享并发入口，但不走 `validate_gm_response()`、`adjudicate()` 或 `complete_turn()`。结果只写入 `image_sessions.prompt_draft`。

### 4.5 Images API 适配器

新增独立 `OpenAIImageProvider`：

- 路由规范化：Base URL 根地址自动补 `/v1`，完整 `/v1` 不重复拼接。
- `POST /images/generations`，Bearer 鉴权。
- 不发送 `temperature`、thinking、`response_format` 等文本模型参数。
- 只接受固定模型；`size` 严格限制为 `1024x1024`、`1536x1024`、`1024x1536`，`quality` 严格限制为 `low/medium/high/xhigh/max/auto`，格式固定 PNG。
- 响应体上限、`data` 恰好一项、Base64 严格解码、PNG 魔数/MIME、像素尺寸、字节数上限全部校验；保存 provider request ID、`usage` 及响应中可用的 size/quality/output_format。
- 401/403、429、5xx、超时、网络错误沿用稳定错误码；正式生图不做隐藏重试，避免重复计费。
- 不接受供应商返回的任意文件路径；如返回 URL，首版应拒绝并要求 `b64_json`，避免服务端任意外连下载。

### 4.6 图片存储与访问

文件写入：

```text
apps/api/.data/images/<save_id>/<session_id>/<attempt_id>.png
```

写入流程：临时文件 → 校验 → 原子改名。数据库仅保存相对路径，不保存 Base64 或绝对路径。

接口建议：

- `POST /api/saves/{save_id}/image-sessions`
- `GET /api/saves/{save_id}/image-session`
- `PATCH /api/saves/{save_id}/image-session/{id}/prompt`
- `POST /api/saves/{save_id}/image-session/{id}/generate`
- `GET /api/saves/{save_id}/image-session/{id}/attempts/{attempt_id}`
- `GET /api/saves/{save_id}/image-session/{id}/image`
- `GET /api/saves/{save_id}/image-session/{id}/download`
- `POST /api/saves/{save_id}/image-session/{id}/complete`
- `POST /api/saves/{save_id}/image-session/{id}/cancel`

图片读取必须通过数据库解析相对路径并校验其仍位于图片根目录；设置 `Content-Type`、`Content-Length`、`ETag`、`X-Content-Type-Options: nosniff`。下载接口使用安全文件名和 `Content-Disposition: attachment`。

“完成”采用持久清理状态：先在事务内把会话标记 `completing` 并禁止 worker 写入，提交后幂等删除文件，最后标记 `completed`；删除失败保留清理墓碑供启动时重试。删除存档同样先让运行任务失效，worker 在原子改名前后复查 save/session/attempt 状态，防止迟到结果重建孤儿目录。

## 5. 前端设计

### 5.1 入口

将 `GameWorkspace` 的 `.game-header` 右上角加入“生成此刻图片”按钮：

- 已配置：主/次操作样式正常可用。
- 未配置：使用弱化样式和说明图标，但不要使用原生 `disabled`，因为仍需响应点击并提示配置。
- 点击未配置入口时显示轻量提示，提供“前往设置”操作。
- 仅最新节点可新建会话；历史节点入口说明“只能为最新节点创建图片”。已有未完成会话始终可进入。

### 5.2 图片工作区

新增路由：

```text
/saves/:saveId/game/image
```

页面按状态展示：

1. `prompting`：显示“正在根据当前剧情整理画面提示词”。
2. `prompt_ready`：展示可编辑 textarea、字符计数和“生成图片”。
3. `generating_image`：保留已确认提示词只读摘要，显示持久任务进度和取消入口。
4. `image_ready`：显示图片、放大浏览、保存图片、“按修改后的提示词重新生成”和“完成”。
5. `failed/interrupted`：保留提示词和上一张成功图片，显示可操作错误与重试。

在提示词编辑区与“生成图片”按钮之间增加“图片设置”：

- 画幅使用三个单选项：横图 `1536×1024`、方图 `1024×1024`、竖图 `1024×1536`。
- 质量使用六个单选项：低 `low`、中 `medium`、高 `high`、超高 `xhigh`、最高 `max`、自动 `auto`。
- 默认横图 + 高质量。每个质量选项旁说明“更高质量通常更慢且费用更高”；最终请求前再次展示模型、画幅和质量。
- 生成中锁定本次设置；生成完成后可修改设置并用当前提示词再次生成。
- 恢复页面时显示 session 草稿设置；查看某张历史成功图片时显示该 attempt 实际使用的画幅与质量。

放大使用原生 `<dialog>`，保存使用下载接口。图片元素设置明确 alt；在图片生成完成前不猜测图像内容，成功后 alt 可使用提示词的短摘要。

“生成此刻图片”按钮属于 game header 的文档流右侧操作，在窄屏下降到标题信息下方，不能使用绝对定位覆盖长角色名。图片工作区应处理提示词生成中、图片生成中、失败、结果就绪、旧节点会话、未配置模型和无最新节点等状态；对不可用原因使用可点击提示或说明文本，不能只靠灰色 disabled 状态传达。

提示词编辑采用短延迟自动保存并显示“保存中/已保存”；PATCH 携带 `expected_prompt_revision` 防止多页签覆盖。点击“生成图片”时，服务端在同一事务内保存最终文本、递增 revision 并创建绑定该 revision 的 attempt。存在未保存编辑时离开页面需提示。

### 5.3 恢复和隔离

- 进入页面先读取当前活动会话，再决定创建还是恢复。
- 轮询请求绑定 `saveId + sessionId + attemptId + 前端会话 token`，切档后迟到响应不得更新当前页面。
- 页面卸载只中止浏览器请求，不取消后端任务。
- 图片 URL 加 attempt/ETag，避免重新生成后浏览器继续显示旧图。
- 完成后清空本地组件状态并返回剧情页；只有完成接口成功后入口才允许创建下一会话。

## 6. 并发、取消与成本控制

- 提示词生成复用剧情模型的 provider admission，但图片生成使用独立且固定为 1 的并发槽。
- 同一存档的图片会话不阻止正式剧情生成；两者读取同一冻结节点，但不能共享可变任务状态。
- 图片生成请求一旦发出可能无法真正中止。取消采用现有两阶段语义：先 `cancel_requested`，供应商返回后丢弃结果并转 `cancelled`；迟到图片不得落盘。
- 不自动重试超时、429、5xx 或格式错误；所有重试由用户明确触发并提示可能再次计费。
- 请求发出后超时或断线进入 `outcome_unknown`，记录本地请求 ID、派发时间和已获得的 OpenAI request ID；重试前明确提示上一请求可能已产生费用，不能宣称本地幂等可消除供应商侧重复计费。
- 创建图片前显示模型名、尺寸和质量；连接测试和正式生成都标注可能产生费用。
- `xhigh`、`max` 和 `auto` 不承诺固定成本或耗时；UI 不显示未经官方定价接口核算的硬编码金额，只提示相对成本并在请求前确认。

## 7. 数据迁移与清理

- 新增迁移，不修改既有迁移校验和。
- 旧设置默认 `image_model.configured=false`。
- 删除存档时级联删除数据库会话，并安全删除该存档对应图片目录。
- 启动时清理无数据库引用的临时文件及过期已完成记录。
- 存档导出明确排除 `image_sessions`、`image_attempts`、图片文件和生图密钥。

## 8. 实施顺序

### 阶段 A：契约和存储

- 增加生图设置、独立密钥、迁移、会话/尝试仓储。
- 在会话与 attempt 中加入 `size`、`quality` 快照及服务端允许值校验。
- 定义 `image-prompt/1` 契约和状态机。
- 验证设置 CAS、唯一活动会话、幂等及重启中断。

### 阶段 B：提示词生成

- 实现完整上下文的图片提示词消息构建。
- 增加独立 worker，不写剧情或权威状态。
- 验证冻结节点、切档隔离、提示词格式及错误恢复。

### 阶段 C：图片生成与本地文件

- 实现 `OpenAIImageProvider` 和 `/images/generations` 调用。
- 完成 Base64、PNG、大小、路径、原子写入与下载校验。
- 验证无隐藏重试、取消迟到结果和重复计费防护。

### 阶段 D：设置与图片工作区

- 设置页增加生图模型和独立 API Key。
- 游戏页增加入口、恢复提示和图片路由。
- 完成提示词编辑、画幅与质量设置、轮询、放大、下载、重新生成和完成复位。

### 阶段 E：综合验证

- 后端单元/集成测试、前端 Vitest、类型检查和生产构建。
- 使用假 Provider 覆盖完整流程，再由用户明确同意后执行一次真实 Sunburst 低成本测试。
- 检查存档导出、日志、错误响应及 Git 暂存内容均不包含密钥、Base64 图片或本机绝对路径。

## 9. 核心测试矩阵

- 未配置时入口提示并可跳转设置，不能创建会话。
- 已配置时只允许 `gpt-image-2.5-sunburst`，无效地址、模型和 Key 被拒绝。
- 提示词请求包含全部冻结上下文，但不创建 turn/version/journal/change。
- 提示词可编辑，生成请求绑定准确的 `prompt_revision`。
- 横图、方图、竖图分别映射到 `1536x1024`、`1024x1024`、`1024x1536`；六档质量正确映射到 `quality`。
- 非允许的 size/quality、客户端伪造方向或与 request fingerprint 不一致的参数被后端拒绝。
- 图片尝试开始后修改 UI 设置不会改变运行中 attempt；重新生成使用新设置并保留旧 attempt 元数据。
- 刷新、切页、切档、重启后恢复同一会话和任务进度。
- 未完成会话阻止为新节点创建第二会话，但允许返回旧会话。
- 历史节点没有活动会话时不能创建图片；已有旧节点会话仍可恢复、保存图片和完成复位。
- 两个浏览器页签同时编辑提示词时，旧 `prompt_revision` 保存返回冲突，不静默覆盖新草稿。
- 生成成功后图片可展示、放大和下载；重生成不会误显示旧缓存。
- 取消、超时、限流、服务错误均不隐藏重试；迟到结果不落盘。
- 请求结果不确定时显示可能已产生费用，用户确认后才能再次请求。
- 完成后本地图片与草稿清理，入口恢复可创建状态。
- 删除存档同步清理图片；导出不包含图片、会话或生图密钥。
- 路径穿越、超大响应、非法 Base64、错误 MIME/魔数及重复 request ID 全部拒绝。

## 10. 完成标准

- 用户从当前最新剧情节点可完整执行“生成提示词 → 编辑 → 生图 → 放大/保存 → 重生成 → 完成复位”。
- 离开页面和服务重启不丢任务状态，跨存档响应不会串入。
- 图片流程不改变任何游戏权威状态或剧情历史。
- 所有收费请求均由用户明确触发，没有隐藏重试。
- 应用只在本机持久化密钥和图片，不进入存档、日志或 Git；发送到剧情模型服务和 OpenAI 的数据范围在首次使用前明确告知用户。
- 自动化测试、Python 编译、前端类型检查与生产构建全部通过。
